# Assignment 04 参考答案

## SFT

### 1. SFT 与预训练的 label 差异

预训练把所有真实文本都当作目标；SFT 只把 assistant 回答当作目标。
SFT 要教会模型“在 user 提问之后以 assistant 身份回答”，
因此 user/system 文本是条件，不是模型应该输出的内容。

### 2. system/user 是否参与 loss

不参与。它们参与前向计算（作为 context），但 label 设为 `-100`。

### 3. SFT 学习率为什么更小

SFT 数据量远小于预训练，且模型已经具备语言能力；
过大的学习率会破坏预训练学到的知识（灾难性遗忘/不稳定）。

## 生成

### 4. 一次生成一个 token 与前向的关系

每次前向都会得到最后一个位置对所有词表的 logits。
训练时一次前向输出整段 logits 是为了并行计算所有位置的 loss；
生成时只需要最后一个位置，配合 KV cache 每次只算新 token。

### 5. temperature

temperature 在 softmax 前缩放 logits：

- `T > 1`：分布更平坦、更随机；
- `T < 1`：分布更尖锐、更确定；
- `T → 0`：概率集中到 argmax。

直接除 0 会报错；应在实现中把 `T <= 0` 当作贪心（argmax）处理。

### 6. top-k 作用在 logits 还是概率

一般作用在 logits（softmax 单调，排序不变），把第 k 大之外的分数设为 `-inf`。

### 7. top-k / top-p 解决什么

两者都用于剪掉低质量的长尾候选：

- top-k：固定保留概率最高的 k 个；
- top-p：动态保留累计概率达到 p 的最小集合。

目的都是减少模型退化带来的重复、无意义文本。

### 8. repetition penalty 为什么区分正负

对已出现 token，正分除以惩罚值、负分乘以惩罚值，
在降低其被选中概率的同时不改变分数符号方向。

### 9. 生成退化与采样方法

最大似然训练让模型对“可能但重复”的文本也分配不低的概率；
自回归采样逐步累积误差，长序列更容易进入重复循环。
top-k、top-p、temperature 等方法通过截断/重塑分布缓解。

## 完成自检

1. `temperature=0` 会导致除零；应在代码中把它当作贪心生成。
2. 顺序会影响结果，通常先 top-k 后 top-p；实现要保证两者在同一份 logits 上依次截断。
3. 最后一个位置的 logits 已经包含全部前文信息，生成只需要这一个位置；
   其余位置的 logits 不会在下一步被用到。
